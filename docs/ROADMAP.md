# 易码 EzQR-Tools 路线图

## 愿景

把 EzQR-Tools 做成一个 **Local-first 的桌面二维码工作台**：

- 默认不需要上传内容，不需要接口密钥。
- 文本生成、图片解析、重构和导出都能在本机完成。
- 在线接口保留为可选能力，而不是核心运行前提。
- 保持浅色液态玻璃界面与轻量、清晰的桌面体验。

当前 `v7.2.0` 已完成本地编码、本地解析和完整离线重构。默认无需 API Key；保留显式选择的草料适配器。后续版本仍为规划。

## 技术原则

1. **引擎可替换**：业务层只依赖 `QrCodeEngine` 接口，不直接绑定草料或某个本地库。
2. **本地优先**：离线时核心流程必须可用，在线能力只负责增强。
3. **输出兼容**：默认仍输出 1024×1024 PNG，支持尺寸、纠错级别和边框配置。
4. **可验证**：每个引擎都要通过统一的内容、Unicode、长文本、纠错级别和解码一致性测试。
5. **隐私明确**：界面清楚显示当前使用本地引擎还是在线接口。

```ts
interface QrCodeEngine {
  readonly id: "local" | "caoliao";
  readonly supportsDecode: boolean;
  encode(content: string, options: QrOptions): Promise<Buffer>;
  decode(image: ImageBytes): Promise<string[]>;
  health(): Promise<EngineHealth>;
}
```

## v7.1：本地二维码生成（已完成）

**目标：文本生成完全脱离草料。**

- 在主进程新增 `QrCodeEngine` 抽象与 `LocalQrEngine`。
- 使用 `qrcode@1.5.4` 生成像素矩阵，并封装为内部适配器。
- 支持 1024×1024 PNG、L/M/Q/H 纠错级别、0–16 边框、中文、URL 和多行文本。
- 文本生成、图片重构中的“重新生成”步骤默认统一调用本地编码器；明确切换草料后才使用在线生成。
- 保留在线引擎作为可切换适配器，但默认不再调用生成接口。
- 添加金标准测试：相同内容在本地产物与参考二维码之间完成二次解码一致。

验收标准：

- 断网状态下可以生成并下载二维码。
- 中文、URL、多行文本和 900 字符附近内容生成正常。
- 生成尺寸、纠错级别和边框与配置一致。
- 可以生成900字以上内容

实现约定：

- 默认参数为 1024×1024、M 纠错、2 模块边框，可在设置中调整。
- 超过 900 字符不再按旧接口建议阻止或警告；950 个常见汉字使用 L 纠错验收，实际容量由内容编码模式与纠错级别决定。
- 超出容量或尺寸不足时明确报错，不自动降低纠错、不自动切换到在线服务。
- `qr.engine` 保存生成引擎选择，旧配置默认 `local`；本地生成无需 API Key。
- 图片解析仍联网；启动不自动调用草料生成探针，手动检测和 GitHub 静默更新保留。

## v7.2：本地二维码解析与重构（已完成）

**目标：图片解析和自动重构都不再依赖草料。**

- 固定使用 `zxing-wasm@3.1.6/reader`，封装为 `LocalDecodeEngine`；仅识别二维码，启用旋转、反色与增强检测，Plain 模式保留原文。
- 使用 Chromium/Canvas 将常见图片格式转换为解码输入，支持 PNG、JPG、BMP、GIF、WebP。
- 将“解码 → 本地编码 → 保存 → 历史记录”串成完整离线链路。
- 对低分辨率、旋转、透明背景、多码图片和二维码区域偏移进行回归测试。
- WASM 二进制随生产依赖纳入 ASAR，从包公共路径读取并校验 SHA-256，以 wasmBinary 初始化；首次加载后复用，加载失败清理缓存并允许重试，不使用 CDN。
- `qr.engine` 同时控制解析与生成，请求携带参数快照；保留 schemaVersion 2、旧选择、设置防抖与写入队列。
- 源图最多 32 MiB、单边 8192、总像素 16777216，转换 PNG 最多 64 MiB；只限制二维码输入，不限制背景选择。
- 多码按位置排序，保留全部结果并重构首个；转换到保存全程忙碌，失败可重试且不写成功历史。
- 完整测试、打包与离线产物验收见 [v7.2.0 交付报告](releases/v7.2.0-validation.md)。

验收标准：

- 断网状态下完成“选择图片 → 解码 → 重构 → 保存”。
- 重构结果再次离线解码后内容一致。
- 不需要草料 API Key 即可使用全部核心功能。

## v7.3：离线优先与在线适配器

**目标：持续完善离线与在线兼容体验。**

默认本地、统一处理引擎、无需 API Key 和普通流程文案已随 v7.2 提前完成；以下保留为后续体验回归方向。

- 默认引擎改为本地引擎；草料接口只保留在“在线增强”或兼容性设置中。
- 默认设置不再要求接口密钥，启动时不再以在线状态作为核心状态。
- 增加引擎状态、离线提示和网络恢复后的手动切换能力。
- 将 v7.1 的 `qr.engine` 生成选择扩展到完整编码/解码策略，提供旧配置无损默认值。
- 清理草料 API 在普通流程中的提示与错误文案。

验收标准：

- 首次启动、断网启动和长期离线使用均无阻塞。
- 关闭在线模式后界面不出现错误状态。
- 旧配置可继续读取，不丢失历史与保存设置。

## 质量门槛

每个离线版本必须通过：

- 单元测试：配置、引擎参数、路径、历史记录和错误处理。
- 端到端测试：断网生成、图片重构、保存和再次解码。
- 视觉回归：浅色工作台、设置、历史记录和弹窗。
- 打包验收：WASM/本地编码依赖被正确收集，便携目录可启动。
