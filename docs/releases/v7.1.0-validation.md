# 易码 EzQR-Tools v7.1.0 交付与验收报告

日期：2026-10-19（Asia/Shanghai）

## 1. 修改概述

本地二维码生成已实现：默认 qrcode 编码，草料保留显式在线适配器；图片解析仍通过草料。文本生成和重构重新编码统一调用 QrCodeEngine。新增生成引擎、尺寸、纠错、边框设置，旧配置缺失引擎字段时默认本地。每个任务携带参数快照，设置写入串行处理并保留尚未保存的新选择，防止快速切换引擎时误用旧在线设置。

保留中文、URL、多行、emoji 和首尾空白；文本导入继续规范换行，但不再裁掉首尾空白。移除旧的 900 字提示和 2000 字导入限制，保留 5 MB 文件及 50000 字符保护。本地容量或尺寸不足时明确报错，不自动降低纠错、不自动联网重试。对 qrcode 部分尺寸的浮点向下取整问题作内部条件补偿，确保输出尺寸准确。

版本升级为 7.1.0，更新文档、公告、许可与实际界面截图，保留原有浅色玻璃、胶囊滑块及弹窗交互。未引入本地解码生产依赖。源码发布到 main 分支，使用 v7.1.0 标签和 GitHub Release 分发安装器及校验文件。

## 3. 测试与检查行为

在项目根目录执行：

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npx --no-install playwright test tests/e2e/app.e2e.ts --output test-results/final-app-check
npm run dist:win
$env:QRTOOL_PACKAGED_EXECUTABLE = (Resolve-Path 'release/win-unpacked/EzQR-Tools.exe').Path
npx --no-install playwright test tests/e2e/packaged.e2e.ts --output test-results/packaged-check
npm audit --omit=dev --json
git diff --check
Get-FileHash -LiteralPath release/EzQR-Tools-7.1.0-x64-Setup.exe -Algorithm SHA256
```

另完成参数截图复验及 ASAR 清单检查，确认 qrcode、pngjs、dijkstrajs 和编码器许可进入产物，测试解码器 jsQR 与 zxing 均未进入应用包。没有向草料上传真实用户图片；在线行为由本地模拟接口验证。

## 5. 剩余风险与 review 重点

- 图片解析仍需草料与网络，本版本只承诺本地编码；GitHub 静默更新和手动接口检测仍会联网。
- 单码容量由编码模式和纠错决定。950 个常见汉字需选 L 等足够容量配置；密集长文本建议增大留白或尺寸，不承诺任意纠错级别都能容纳。
- 某些密集高版本二维码超出 jsQR 定位能力，因此长文本独立解码用例明确选择了可稳定验证的参数；生产输出仍使用标准 qrcode PNG。0 边框在独立扫码时应留外部白底。
- 安装器未签名，SmartScreen 可能提示；默认数据保存在程序目录，卸载前需备份。
- 完整依赖安装审计保留原有 8 项 moderate 开发工具链告警，生产依赖为 0；未执行可能引入破坏性升级的 audit fix --force。
- 构建器有依赖重复引用日志；测试运行器有 NO_COLOR/FORCE_COLOR 环境提示，均未影响构建或验收。
- 延迟设置的 E2E 使用固定 Electron 版本的内部 IPC handler 注入，升级 Electron 时需复核该测试。
