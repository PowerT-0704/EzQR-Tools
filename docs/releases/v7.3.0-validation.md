## 1. 修改概述

左侧按“图片重构 → 文本生成 → 二维码解析”排列，默认工作区不变；新增 Ctrl/Cmd+3 切换独立解析。新页面复用原有玻璃卡片、胶囊导航、图片选择/拖入、媒体协议、Chromium 转换和本地 WASM，只显示原始解码内容，不编码、不生成或保存图片，也不写历史。

新 IPC `qr:decode` 和 `qrTool.decode()` 接收 `DecodeRequest { operationId, path, normalizedPng }`，返回 `DecodeResult { contents, sourcePath, sourcePreviewUrl }`，进度种类新增 `decode`。主进程校验请求、路径与 PNG 后直接调用 LocalDecodeEngine，不读取引擎设置、不调用草料适配器或输出/历史服务。即使全局选中草料，此功能仍固定本地。

多码按位置排序，保留全部结果及重复内容；结果栏完整显示原文并逐条复制，不去除首尾空白或截断长内容。右侧仅预览原图，无重构、下载及输出目录按钮。独立解析工作区的标题与页脚明确显示本地状态，不显示接口检测；设置说明区分全局引擎开关的作用范围。

图片转换到结果返回全程有独立忙碌状态、任务编号和阶段文字；采用扫描线与加载环动画，支持减少动态效果。切页不串用任务进度或强制切回，重复任务被拦截。失败清空旧结果，可重试同一路径；转换资源在 finally 释放。原有格式、首帧、旋转、反色、白底转换、32 MiB/8192 单边/16777216 像素/64 MiB PNG 限制均复用。

回归中发现多次解析会挤出旧工作区的预览资源，现用有限的预览槽保留背景、生成、重构及解析当前使用的资源，维持媒体缓存 40 项上限；新结果替换后旧资源仍可淘汰，并新增缓存边界单测。最小窗口下调整导航图标与字号，避免五字导航标题折行。

版本、测试断言、打包校验及公告更新为 7.3.0。用户确认后，将 Electron 44.9.0 升至 44.9.1，fast-uri 传递依赖从 3.1.8 更新到 3.1.9；未新增第三方库，配置 schema 与历史结构保留。README、路线图、发布说明与官网入口同步更新。未直接读取或编辑现有用户配置、.env、密钥或证书。所有验收仅使用独立临时数据目录。

- Electron 44.9.1 修补 [GHSA-jr5w-w6x2-84p9](https://github.com/electron/electron/security/advisories/GHSA-jr5w-w6x2-84p9) 的证书信任问题；安装与打包均核对实际版本。fast-uri 3.1.9 修补其 URI 处理告警。全依赖及生产依赖审计均为 0。

- 安装器未签名，未运行 NSIS 安装/卸载向导；已实际启动 win-unpacked 验证核心流程。
- 模糊、遮挡或缺少留白的二维码仍可能无法识别；大图转换有短时内存开销，输入上限不变。
- 独立解析结果仅保存在当前应用运行内存中，不写历史，退出后不保留。
