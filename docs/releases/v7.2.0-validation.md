## 1. 修改概述

本地引擎现在同时支持解析和生成：选择或拖入图片后，由 Chromium 通过已有媒体协议读取并转换为白底 PNG，主进程校验路径、大小、PNG 头及尺寸，再由固定版本 zxing-wasm@3.1.6 reader 解码、本地 qrcode 编码、保存并记录历史。保留原图预览和文件命名。GIF 取首帧，支持 PNG、JPG/JPEG、BMP、GIF、WebP。

WASM 从依赖包公共路径读取，在 SHA-256 校验后通过 wasmBinary 初始化，首次使用时加载并复用；失败清除缓存、允许重试，不访问 CDN 或自动上传。仅检测二维码，使用 Plain 文本模式、旋转、反色及增强检测。全部识别结果按检测区域最上方 y、最左方 x 排序，保留重复内容，重构首个并显示数量。

“处理引擎”统一控制解析与生成，默认本地；保留旧配置中有效的草料选择。请求在图片转换前取得参数快照，保留既有防抖、写入队列与旧响应合并逻辑，避免快速切回本地时误上传。在线分支仍上传原始图片。CSP 只为转换增加现有 qrtool-media: 协议，不允许渲染器连接外网或任意读取文件。

二维码源文件上限 32 MiB，单边 8192、总像素 16777216，规范化 PNG 上限 64 MiB；超限明确提示裁剪或缩小，不静默降采样。背景图片不受这些新增限制。转换到保存全程防重复，资源在 finally 中释放，失败可重试同一图片；保存失败、容量不足、无二维码、损坏图片和组件加载失败分别提示。历史变更串行写入，成功落盘后提交内存状态，失败不会新增成功记录。

版本、README、公告、路线图、发布说明、第三方许可和实际截图已更新。保留 schemaVersion 2、二维码容量与参数规则、保存路径、浅色玻璃、胶囊滑块和独立弹窗；未直接读取或编辑现有用户配置、.env、密钥或证书。测试全部使用独立临时数据目录。GitHub 静默检查与手动接口检测仍保留。

截图中的启动错误已修复：本地解码器的模块加载变量与 electron-vite 注入的 require 重名，现已改名。生产构建语法检查和打包应用实际启动均通过。另修正了媒体协议读取所需的 CSP，容量异常测试图提高到足够分辨率后，完整异常恢复回归通过。

发布文档补充：README 增加项目介绍、CDUT（成都理工大学）学生个人项目说明、正式下载与 SHA-256 验证、首次离线操作、升级备份、数据目录回退、保存命名、Word 导入条件及容量常见问题。发布准备仅修改文档，不更改运行代码或安装器，复用已通过离线验收且哈希匹配的产物。

发布操作采用先创建草稿、上传安装器与校验文件、核对附件大小和 GitHub digest，再转为正式 Latest 的流程。仅上传这两个文件，不上传 ZIP、blockmap 或 latest.yml。最终提交号、远程引用与附件核对结果在发布完成后的交付消息中给出。

- 未运行 NSIS 安装/卸载向导；已从其 win-unpacked 同版本产物实际启动并验证完整离线流程。未签名安装器仍可能出现 Windows SmartScreen 提示。
